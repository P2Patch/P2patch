+package org.jolokia.http;

+/*
+ * Proof-of-vulnerability for finding-cea32a9afd67 (CWE-079).
+ *
+ * Root cause: the "callback" request parameter (JSONP callback name) is written
+ * verbatim into the HTTP response body -- which is served with a
+ * script-executable content type ("text/javascript") -- without any validation
+ * that the value is a syntactically-safe JavaScript identifier. Any character
+ * sequence supplied by an untrusted client therefore becomes live, executed
+ * JavaScript in whatever context loads the Jolokia endpoint via <script src=...>.
+ *
+ * This drives the vulnerability through the REAL, unmodified public entry point
+ * org.jolokia.http.AgentServlet#doGet(HttpServletRequest, HttpServletResponse),
+ * exactly as a browser/attacker request would, using EasyMock only to fake the
+ * servlet container plumbing (request/response objects) -- the exact same
+ * technique the project's own AgentServletTest#withCallback() test uses.
+ *
+ * With default configuration (streaming enabled, the project default), the
+ * request flows:
+ *   AgentServlet.doGet
+ *     -> executeRequest -> sendResponse (AgentServlet.java:472 getParameter("callback"))
+ *     -> sendStreamingResponse (AgentServlet.java:485/495 callback passthrough)
+ *     -> IoUtil.streamResponseAndClose (IoUtil.java:30-36) <-- SHARED SINK
+ *
+ * IoUtil.streamResponseAndClose is the shared root-cause sink: it is called
+ * both from AgentServlet (servlet flavor) and from
+ * org.jolokia.jvmagent.handler.JolokiaHttpHandler#sendStreamingResponse (JVM
+ * agent flavor, fed by ParsedUri-parsed query parameters). Fixing validation
+ * only in one caller and not centrally in IoUtil (or replicating the same
+ * validation in every caller) leaves the other flavor exploitable. In addition,
+ * two *non-streaming* sinks exist that IoUtil does not cover and must be fixed
+ * independently:
+ *   - AgentServlet.sendAllJSON (AgentServlet.java:500 "content = callback + ... ")
+ *   - JolokiaHttpHandler.sendAllJSON (JolokiaHttpHandler.java:364, same pattern)
+ *
+ * This PoV exercises the shared IoUtil-backed streaming path (the default
+ * runtime behavior for both agent flavors) to demonstrate the missing
+ * validation at its common root cause.
+ *
+ * Vulnerable behavior (current code): the malicious callback value is echoed
+ * byte-for-byte, unescaped, as the leading JavaScript statement of a
+ * text/javascript response -> exits 0.
+ *
+ * Patched behavior (expected): the callback is validated against a safe
+ * identifier pattern (letters/digits/"_"/"$"/"."/"[]") and either the request
+ * is rejected or the unsafe value is stripped/escaped before being written, so
+ * the raw payload no longer appears verbatim as the response prefix -> the
+ * assertion below fails and the process exits non-zero.
+ */
